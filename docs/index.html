CSCE 567 FINAL PROJECT

Email Triage Needs More Than Text

Comparing message language and email context for safer spam-filtering decisions.

This case study compares text and email-context signals for spam triage. It tests whether either signal family improves the model and whether precision targets chosen on validation data hold up on a separate test set.

01 · THE DATA

Each email carries two kinds of evidence

The cleaned dataset combines message language with structural information from email headers and MIME content. Source-folder labels were used only to verify the join and were excluded from modeling.

02 · SIGNALS

Text patterns and email structure both vary by outcome

These summaries are descriptive, not rules. No individual feature is enough to decide whether an email should be blocked.

04 · SIX-MODEL ABLATION

Text wins the selection, but the margin is tiny

Naive Bayes with text-only features had the best validation average precision. Combined Naive Bayes was nearly tied and slightly higher on the held-out test set, which is not enough evidence to replace the validation-selected model. Both algorithms receive the same feature matrices for each signal condition.

05 · ACTION

The selected cutoffs do not fully hold on the test set

The policy selects a 75% precision cutoff for review and a 95% cutoff for blocking on validation data, then evaluates those exact cutoffs once on the held-out test set. Blue is legitimate email and red is spam: ideally blue appears only in Deliver, red only in Quarantine, and the review band is empty.
